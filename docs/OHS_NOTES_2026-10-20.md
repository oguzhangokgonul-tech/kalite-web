# OHS Note Pool

## Scope

- Mobile Center now opens `ISG Notu Olustur` instead of direct OHS action creation.
- Existing OHS action list and direct creation route remain available with their
  existing permissions. Sidebar adds a separate note pool.
- All authenticated active users of the selected company, including viewers,
  can create and read notes when the OHS module is enabled. No public submissions.
- Only author, company admin, management representative, or top-level super admin
  can edit/soft-delete a note, still within the selected company's scope.
- Existing `actions.create` permission controls conversion. No new permission
  catalog entry is needed for the explicitly universal company note workflow.
- Conversion opens the existing action form with title/description prefilled.
  Assignee, deadline, attachments and notifications reuse the action workflow.
- One note converts once. Versioned writes reject stale edits/deletes/conversions;
  failed form validation retains the original note version for retry safety.
- Note removal keeps its audit record and linked action. Actions sourced from
  notes cannot be hard-deleted, matching existing source-traceability guards.
- Links from note to action respect action-view permission; action to note links
  only expose non-deleted notes in the current company.
- Search, status filter, pagination, native labeled form fields, and mobile layout
  are included. New note submissions do not introduce additional email traffic.

## Data and Audit

New table: `ohs_notes`; Alembic revision `202610200001`, parent `202610140001`.
Runtime schema creates the same model table idempotently. Existing action data
is not transformed. Upgrade/downgrade/upgrade was rehearsed on a disposable SQLite
database; downgrade drops notes and is not a production rollback procedure.

Create, edit, soft-delete and conversion write manual audit events including
company, actor and old/new values in the same transaction. The linked action
history retains the source note number and title.
